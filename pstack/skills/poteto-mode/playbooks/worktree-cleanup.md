### Worktree and simulator cleanup

1. Snapshot and audit. Record `df -h /`, then run `scripts/worktree-audit.sh [-b <pr-base-ref>] [--threads <tsv>] [repo-path]` (principle-build-the-lever). Without `-b` it checks `MERGED` against origin's default branch as GitHub reports it, so pass `-b origin/<branch>` when PRs target another branch. It reads paths from `git worktree list`, never hand-typed, since a hand-typed `~/lim-v2/code/wt/x` misses one T3 made under `~/lim-v2/service/t3code/prod/data/worktrees/` (principle-encode-lessons-in-structure). It classifies each worktree by size, age, merge state, uncommitted work, PR state, and the newest T3 thread bound to it, then suggests a bucket. The script can't call T3, so first export this project's threads for its `--threads <tsv>` argument. Page through `t3_thread_list`, run `t3_thread_read` with `limit: 1` on each for its `worktreePath`, and write one `worktree, thread, status, updated` row per thread. The export is many reads, so hand it to a subagent.
2. The bucket is advice, not permission. The pinned and active threads are the real artifact (principle-prove-it-works). Get that set from the user or the T3 sidebar and cross-check every candidate. The lever has marked `safe` a worktree the user had pinned, so the pinned set wins.
3. Verify usage before deleting. For every `verify-recent-chat` row, or anything you doubt, fan subagents out to read the threads with `t3_thread_read` and report whether the thread is ongoing and which worktrees it touches (principle-guard-the-context-window, threads are bulk). A pinned thread's subagents spawn arena and repro trees into sibling worktrees, and those are in use even when no thread is bound to them. Pick each subagent's effort for the job, per the Subagents section.
4. Pause on irreversible loss. `wip:N` is N tracked uncommitted edits. Show the diff and get a decision first, since removing a clean worktree is recoverable from its branch but uncommitted work is gone. `scratch:N` is untracked throwaway, safe to drop, but name the files. Per Autonomy, clean and merged and not-in-use proceeds. `wip` and in-use pause.
5. Prune the confirmed set. Per path, `git worktree remove --force <path>`. If the dir survives on ignored build artifacts, `rm -rf` it, then `git worktree prune`. Branch refs survive, so no commits are lost. Confirm with `df -h /` and re-list.
6. Simulators and other reclaimers. This Linux box has no simulators, so caches are the next-biggest win: `~/.npm` (`npm cache clean --force`), `uv cache prune`, `pnpm store prune`, `bun pm cache rm`, and Docker build cache (`docker system df`, then `docker builder prune`). More when needed: old browser builds in `~/.cache/ms-playwright` and `~/.cache/electron`. On a macOS device host, simulators are usually the biggest win. `xcrun simctl --set testing delete all` (XCTestDevices clones), `xcrun simctl delete unavailable`, and `xcrun simctl runtime list` then `runtime delete <id>` for old runtimes, plus Xcode `DerivedData` and `iOS DeviceSupport`. Clear only caches the user has not said to keep.

This is the one playbook that deletes user state with no code review to catch a slip, so the gates above are the review.

**Reply:** `df -h /` before and after with space reclaimed, the worktrees pruned, and a one-line reason for each held back (in use by which thread, or uncommitted work).
